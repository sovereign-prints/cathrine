What the two commits do
-----------------------

1. "Split customer-facing site into a Render Static Site"
   The customer pages (home, products, gallery, quote) build into ./dist and
   deploy as a Render Static Site. The API, uploaded images and the admin pages
   stay on the existing web service. No database changes at all.

2. "Add website publishing controls to the admin panel"
   New "Website" tab in the admin with an "Update website now" button.

Render setup after merging
--------------------------

  A. Render > Blueprints > sync. This creates the static service.
  B. On the STATIC service, set:
       API_HOST = https://cathrine.onrender.com
  C. On the WEB service, set:
       STATIC_SITE_ORIGINS = <the static site's URL>
       RENDER_DEPLOY_HOOK_URL = <static site > Settings > Deploy Hook>
       AUTO_PUBLISH = false      (see note below)
  D. Redeploy the web service.

  Do B and C before sending anyone to the new address. Until then the static
  site's requests are blocked and the pages will look empty.

About "automatic" publishing
----------------------------

  Your products, prices, gallery images and business details are read from the
  API by the live pages. When you save a change in the admin it is on the
  website immediately. There is nothing to publish and nothing to wait for.

  A rebuild is only needed when the page files themselves change - a new page,
  a design or layout change. That is what the "Update website now" button does.

  If you still want a rebuild fired automatically every time you save content,
  set AUTO_PUBLISH = true on the web service. Edits made close together are
  grouped into one build (2 minute window) so it does not run a build per save.
  It is off by default only because it spends Render build minutes without
  changing what customers see.
